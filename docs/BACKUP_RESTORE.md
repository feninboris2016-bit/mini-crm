# 💾 Резервное копирование и восстановление (BACKUP_RESTORE.md)

В данном документе описан регламент создания резервных копий базы данных Мини-CRM, условия хранения и пошаговая процедура восстановления.

---

## 1. Состав резервной копии

Каждый снимок базы данных сохраняется в формате структурированного JSON файла `backup-YYYY-MM-DDTHH-mm-ss.json` в папке `data/backups/`.

Снимок содержит:
- **`metadata`**: версия схемы, дата и время создания, количество записей.
- **`leads`**: полный массив заявок клиентов со всеми статусами и источниками.
- **`comments`**: все внутренние заметки менеджеров с привязкой к лидам.
- **`jobs`**: история и статусы задач очереди уведомлений.
- **`audit`**: журнал критических действий безопасности.
- **`settings`**: неконфиденциальные параметры конфигурации (пароли SMTP, API-токены и ключи **исключаются** из открытого экспорта в целях безопасности).

---

## 2. Создание резервной копии

### Способ А: Через веб-интерфейс CRM
1. Войдите в личный кабинет CRM.
2. Перейдите во вкладку **«⚙️ Настройки»**.
3. В блоке **«💾 Резервное копирование»** нажмите кнопку **«+ Создать бэкап сейчас»**.
4. Система создаст архив, отобразит размер файла и обновит статус последнего бэкапа.

### Способ Б: Через командную строку (CLI)
На сервере выполните:
```bash
npm run backup
```
Пример вывода:
```
[Backup] Создание резервной копии базы данных...
✅ Резервная копия успешно создана!
📁 Файл: backup-2026-10-27T11-12-50.json
📊 Количество лидов: 48
💾 Размер: 24.5 КБ
```

---

## 3. Восстановление данных из резервной копии

### Способ А: Через веб-интерфейс CRM
1. Откройте вкладку **«⚙️ Настройки»** в CRM.
2. В таблице доступных архивов найдите нужную копию по дате и времени.
3. Нажмите кнопку **«Восстановить»** напротив выбранного файла и подтвердите действие.
4. Система восстановит все лиды и комментарии внутри единой атомарной транзакции базы данных.

### Способ Б: Через командную строку (CLI)
1. Чтобы посмотреть список всех имеющихся копий:
   ```bash
   npm run restore
   ```
2. Чтобы запустить восстановление из конкретного файла:
   ```bash
   npm run restore -- backup-2026-10-27T11-12-50.json
   ```

---

## 4. Регламент тестирования восстановления (Disaster Recovery Test)

Рекомендуется периодически (раз в месяц) проверять возможность восстановления данных в изолированной среде:
1. Запустите тесты проекта:
   ```bash
   npm test
   ```
   В автоматизированный тест-сьют `tests/crm.test.ts` уже встроен тест полного цикла: создание бэкапа, проверка размера, валидация JSON и восстановление в чистую тестовую базу с подтверждением количества записей.
