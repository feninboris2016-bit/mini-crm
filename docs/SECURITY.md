# 🛡️ Модель безопасности (SECURITY.md)

Документ описывает механизмы защиты информации, предотвращения атак и обеспечения конфиденциальности в Мини-CRM.

---

## 1. Аутентификация и защита учётных записей

- **Хеширование паролей**:
  Пароли администраторов хешируются с использованием адаптивного криптографического алгоритма **`bcrypt`** с фактором стоимости (salt rounds) **12**. Пароли в открытом виде никогда не сохраняются в базе данных.
- **Защита от перебора паролей (Brute-Force Protection)**:
  Встроенный трекер попыток входа отслеживает неудачные попытки по IP и email.
  - При 5 неудачных попытках вход блокируется на **5 минут**.
  - При 10 попытках блокировка продлевается на **30 минут**.
  - Время ожидания возвращается клиенту в заголовке `retryAfterSeconds`.
- **Сессии и токены**:
  Используются криптографически подписанные токены **JWT** (HMAC-SHA256) со сроком жизни 7 дней. Токен передается в заголовке `Authorization: Bearer <token>` либо сохраняется в защищённой cookie с атрибутом `httpOnly: true` и `sameSite: 'lax'`.
- **Создание администратора**:
  Первоначальный администратор создается исключительно через консольную утилиту (`npm run create-admin`) или защищённую команду при развертывании. В коде проекта нет захардкоженных учетных записей.

## 2. Защита публичного API от спама и злоупотреблений

- **Honeypot (поле-ловушка)**:
  Форма содержит скрытые поля `_hp_bio` и `website`, невидимые реальным пользователям. Спам-боты, автоматически заполняющие все поля, мгновенно отсекаются сервером.
- **Ограничение частоты запросов (Rate Limiting)**:
  Публичный endpoint приёма заявок защищён скользящим окном: максимум **25 запросов за 15 минут** с одного IP адреса (параметры настраиваются через веб-интерфейс CRM).
- **Ключ доступа сайта (`X-Site-Key`)**:
  Публичный API проверяет заголовок `X-Site-Key`. Попытки отправки заявок сторонними ботами без указания ключа отклоняются с кодом `403 Forbidden`.
- **Идемпотентность**:
  Повторные клики пользователя с одинаковым `X-Idempotency-Key` не создают дублирующих лидов в базе данных и возвращают существующую запись.

## 3. Защита от инъекций и веб-уязвимостей

- **SQL Injection**:
  Все SQL-запросы к базе данных используют исключительно **параметризованные запросы** (`$1, $2, ...` для PostgreSQL и сопоставленные плейсхолдеры для SQLite). Конкатенация пользовательского ввода в SQL-строки категорически запрещена.
- **Межсайтовый скриптинг (XSS)**:
  Входящие текстовые поля очищаются от HTML-тегов (`<`, `>`). В интерфейсе React экранирует все данные при отображении в DOM.
- **CSV Formula Injection (CWE-1236)**:
  При экспорте в CSV все поля проверяются на наличие опасных начальных символов `=`, `+`, `-`, `@`, `\t`, `\r`. При их обнаружении значение автоматически предваряется апострофом `'`, что нейтрализует выполнение вредоносных формул в Microsoft Excel и LibreOffice Calc.
- **Ограничение размера тела запросов**:
  Express ограничивает размер входящих JSON-пакетов до **200 КБ**, защищая сервер от атак типа ReDoS и переполнения памяти.

## 4. Конфиденциальность и маскирование секретов

- **Маскирование в API**:
  Пароли SMTP, токен Telegram-бота и API-ключ сайта при запросе настроек отображаются в маскированном виде (`••••••••` или `1234••••5678`).
- **Очистка текста ошибок очереди**:
  Если провайдер почты или Telegram API возвращает ошибку, содержащую токены или пароли соединения, утилита `sanitizeErrorMessage` автоматически заменяет их на `[TOKEN_REDACTED]` и `password=REDACTED` перед записью в журнал.
- **Журнал аудита (Audit Log)**:
  Критические действия (вход, смена статуса, добавление заметки, экспорт данных, создание бэкапа) фиксируются в таблице `audit_log` с фиксацией IP адреса, но без сохранения паролей и избыточных персональных данных.
